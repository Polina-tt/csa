# Лабораторна робота №2
## «Цілочисельна арифметика процесора»

### Опис проєкту
Проєкт реалізує дослідження цілочисельної арифметики у системах з фіксованою розрядністю (8, 16, 32 біти) мовою C++20. 
Реалізовано перевірку беззнакового переповнення (wrap-around, Carry/Borrow) та прогнозування знакового переповнення (Signed Overflow) без виникнення невизначеної поведінки (Undefined Behavior).

### Структура проєкту
* `CMakeLists.txt` — файл конфігурації для системи збірки CMake.
* `arithmetic.hpp` — заголовочний файл з оголошеннями структур та функцій.
* `arithmetic.cpp` — реалізація логіки безпечних арифметичних операцій.
* `main.cpp` — головний файл із набором тестів для перевірки.

### Як зібрати та запустити (у WSL / Linux)
```bash
cmake -S . -B build
cmake --build build
./build/integer_arithmetic


## Контрольні питання

1. **Що називають розрядністю цілого типу?**  
   Це кількість бітів у пам'яті, яка виділяється під зберігання значення цього типу (наприклад, 8 біт для `int8_t`, 32 біти для `int32_t`). Від розрядності залежить обсяг діапазону чисел, який можна представити.

2. **Який діапазон має N-бітний беззнаковий тип?**  
   Від $0$ до $2^N - 1$. Наприклад, для 8-бітного `uint8_t` це від $0$ до $255$.

3. **Який діапазон має N-бітний знаковий тип у доповняльному коді?**  
   Від $-2^{N-1}$ до $2^{N-1} - 1$. Наприклад, для `int8_t` (8 біт) — від $-128$ до $127$.

4. **Як отримати доповняльний код від’ємного числа?**  
   Треба взяти модуль числа у двійковому вигляді, інвертувати всі біти (отримати обернений код) і додати одиницю до молодшого розряду.

5. **Чому модуль від’ємної межі на одиницю більший за додатну межу?**  
   Через те, що нуль займає окрему комбінацію серед додатних чисел (або знаковий біт забирає половину комбінацій). Наприклад, у 8 бітах є рівно 256 комбінацій: від $-128$ до $127$ (ноль додатний, а мінус 128 має окрему комбінацію без симетричного $+128$).

6. **Що відбувається з беззнаковим результатом, який перевищує максимум?**  
   Виникає закруглення (wrap-around): значення «перегортається» через нуль за модулем $2^N$ (наприклад, $255 + 1 = 0$).

7. **Що таке перенесення з найстаршого розряду (Carry)?**  
   Це прапор, який сигналізує, що під час додавання беззнакових чисел сталася «передача» одиниці далі за межі розрядної сітки (результат не помістився у свій тип).

8. **Що таке позика під час віднімання (Borrow)?**  
   Це прапор, який вказує на те, що при відніманні зменшуване було меншим за від'ємник, через що знадобилося «позичати» одиницю з молодших/старших розрядів (наприклад, $0 - 1$).

9. **Чим carry відрізняється від знакового переповнення?**  
   `Carry` стосується беззнакової арифметики та вказує на вихід за межі діапазону $[0, 2^N-1]$. Знакове переповнення (`Overflow`) стосується знакових чисел і фіксує перехід через межі діапазону у додатну чи від'ємну сторону, що змінює біт знака числа.

10. **За якої умови додавання двох додатних знакових чисел переповнюється?**  
    Коли їхня математична сума перевищує максимально можливе додатне значення для даного знакового типу (наприклад, для `int8_t` це $> 127$). У результаті біт знака випадково стає одиницею, і число стає від'ємним.

11. **За якої умови віднімання може спричинити знакове переповнення?**  
    Коли від додатного числа віднімають велике додатне (або від'ємне від додатного), і результат стає меншим за мінімальне можливе значення для цього типу (наприклад, меншим за $-128$ для `int8_t`).

12. **Чому не можна спочатку виконати небезпечне знакове додавання, а потім перевірити результат?**  
    Тому що в мові C++ переповнення знакових цілих типів викликає невизначену поведінку (UB). Код із UB може бути оптимізований компілятором непередбачувано, і перевірка після факту може просто «не спрацювати».

13. **Що означає невизначена поведінка C++ (Undefined Behavior)?**  
    Це стан програми, за якого стандарт C++ не визначає, що саме має відбутися. Компілятор має право вважати, що такого ніколи не станеться, через що програма може працювати некоректно, аварійно завершуватися або видавати випадкові дані.

14. **Як ширший проміжний тип допомагає перевірити арифметичний результат?**  
    Якщо додати два числа типу `int8_t` у тип `int16_t`, переповнення на рівні бітів не станеться, оскільки ширший тип має достатньо місця для точного математичного результату. Після цього можна безпечно порівняти результат із межами `int8_t`.

15. **Чому `std::uint8_t` може виводитися як символ?**  
    У бібліотеці `<iostream>` тип `std::uint8_t` зазвичай реалізується як синонім (`typedef`) для `unsigned char`. Для потоків виведення `std::cout` символ `unsigned char` сприймається як текстовий ASCII-символ, а не як число. Щоб вивести його як число, використовують приведення до `+val` або `static_cast<int>`.

16. **Що таке цілочисельне просування (Integer Promotion)?**  
    Це процес неявнї конвертації менших цілих типів (`char`, `short`, `int8_t`, `uint8_t`) до звичайного `int` або `unsigned int` перед виконанням арифметичних операцій.

17. **Чим небезпечне змішування знакових і беззнакових операндів?**  
    При порівнянні чи операціях між `signed` і `unsigned` значеннями знаковий операнд неявно перетворюється на беззнаковий. Через це від'ємне число може інтерпретуватися як величезне додатне число, що ламає логіку умов.

18. **У який бік округлюється знакове цілочисельне ділення в C++?**  
    У бік нуля (відкидається дробова частина, наприклад, $-5 / 2 = -2$).

19. **Який знак має остача від знакового ділення?**  
    Знак остачі в C++ завжди збігається зі знаком діленого (першого операнда).

20. **Чому ділення INT_MIN на −1 є окремим небезпечним випадком?**  
    Тому що максимальне за модулем від'ємне число (наприклад, $-128$ для 8 біт) не має додатного еквівалента в межах того самого типу ($127$ — максимум). При діленні його на $-1$ виходить число, яке не поміщається в діапазон, що призводить до знакового переповнення та UB (а на деяких процесорах — до апаратного збою).

21. **Чим відрізняються wrapping, checked і saturating arithmetic?**  
    * **Wrapping:** при переповненні значення циклічно «загортається» (wrap-around).
    * **Checked:** переповнення детектується, і програма повертає помилку або сигналізує про неї.
    * **Saturating:** при досягненні ліміту значення «заморожується» на максимальній або мінімальній межі і далі не змінюється.

22. **Навіщо використовувати `std::numeric_limits`?**  
    Щоб програмно й безпечно отримувати мінімальні та максимальні значення для будь-якого типу даних, роблячи код переносимим між різними платформами.

23. **Які тести називають межовими?**  
    Тести, які перевіряють роботу програми на граничних значеннях діапазонів (наприклад, на мінімумі, максимумі, а також на значеннях «межа + 1» і «межа - 1»).

24. **Чому один успішний тест не доводить коректність функції?**  
    Один тест підтверджує працездатність лише для конкретного набору вхідних даних. Він не гарантує відсутності помилок на інших числах, спеціальних кейсах або межових умовах.

25. **Що перевіряє UndefinedBehaviorSanitizer (UBSan)?**  
    Це інструмент компілятора, який автоматично відстежує виникнення невизначеної поведінки під час виконання програми (зокрема, знакове переповнення, ділення на нуль, некоректні зсуви тощо).

26. **Як перенесення переходит із молодшого слова в старше в багаторозрядному додаванні?**  
    Молодша частина додається окремо, а прапор перенесення (`Carry`) з неї додається як одиниця до старшої частини разом із її власними операндами.

27. **Чому грошові значення часто зручно зберігати в найменших цілих одиницях?**  
    Щоб уникнути похибок округлення, притаманних числам із плаваючою комою (`float`/`double`). Наприклад, суму в гривнях зручно зберігати у копійках як звичайне ціле число (`int64_t`).

28. **Які дані зі звіту дають змогу відтворити експеримент?**  
    Версія стандарту мови (C++20), параметри компілятора (`-Wall -Wextra -Wpedantic`), розрядність і тип середовища (WSL / Linux, версія GCC), а також чітко задані вхідні тестові дані й межі типів.



## 15. Підсумковий висновок

1. **Як фіксована розрядність обмежує результат:** Дослідження показало, що тип даних із фіксованою кількістю бітів може оперувати лише суворо обмеженим набором значень (наприклад, `uint8_t` охоплює діапазон від 0 до 255). Будь-який вихід за ці межі призводить або до циклічного згортання бітів (wrap-around), або до спотворення знака числа.
2. **Чому беззнакова і знакова арифметика мають різні правила виходу за діапазон:** Беззнакові операції спираються на циклічне переповнення та фіксуються прапорами `Carry`/`Borrow`, що є математично передбачуваним у межах машинного слова. Знакова арифметика використовує доповняльний код і вихід за її межі (`Signed Overflow`) за стандартами C++ спричиняє небезпечну невизначену поведінку (UB), тому потребує попереднього аналізу операндів.
3. **Як перевірки, ширші проміжні типи та межові тести роблять обчислення надійними:** Використання проміжних типів (наприклад, `int16_t` для розрахунків з 8-бітними значеннями) дозволяє уникнути переповнення та чітко прогнозувати результати за допомогою `std::numeric_limits`. Успішне проходження межових тестів (що було продемонстровано на тестах нашого Варіанта 1) повністю підтверджує коректність реалізованих функцій безпечної арифметики без ризику апаратних збоїв чи помилок компілятора.
